Learning from the notification you did—or did not—send

Continual personalization needs a learning loop that scores decisions while they are made. When each action reveals only its own outcome, that loop is online.

Start with one late-night receipt

At 10:47 p.m., a receipt lands on a phone. Should the assistant interrupt, put it in tomorrow’s digest, or archive it quietly?

The choice looks simple. Learning from it is not. If the assistant sends a push, it can observe whether that push is opened, dismissed, or ignored. If it archives the receipt, there was no push—so it cannot later claim that the user would have clicked one. The action changes what evidence can exist.

What can be learned after archiving with no later open? Not “archive was correct,” and not “the user would have ignored a push.” Only one factual statement:

We archived this receipt, and the user did not go looking for it during the observation window.

That evidence is weak, but it is real. Researchers call the setting a contextual bandit: one stream of contexts, one action per round, feedback only for the chosen action, and a cost for choosing worse than the best route (regret). There is no clean training phase followed by a separate test phase. Every cold-start mistake counts.

Why online learning fits continual personalization

Preferences are not a fixed label set. Work chat can be urgent on call and unwanted at dinner. A receipt may deserve a digest today and automatic archiving next month. A model that adapts only in infrequent offline retrains misses the stream between those trainings.

Batch supervised learning often assumes that every example has an observable preferred action, and that quality can be summarized on a held-out exam after training. Notification routing breaks both assumptions: unselected routes never produce factual outcomes, and the decisions served during adaptation are the product users experience.

    That is what online learning means here: observe a request, act with currently available information, receive the factual outcome of that action, update for future requests, and accumulate quality on the way. Continual learning needs that same discipline whenever the world keeps moving after any fixed training snapshot.

    Why keep the learner near the user?

    A generic notification model knows average open rates. A personal device needs a model of one person—and that person’s preferences can change without warning. Keeping a learner close to the user lets private history stay local, supports offline decisions, avoids a network round trip for every update, and can use fresh device context.

    The trade-off is compute. Phones have tight memory, energy, and thermal budgets. A realistic edge learner therefore stays small and updates in very small batches. This demo uses LiquidAI/LFM2.5-230M: base weights stay frozen; adaptive methods update a rank-4 LoRA adapter with 172,032 trainable parameters. It is a real language-model experiment inside a simulator, not a phone-battery measurement.

    Why familiar alternatives struggle here

    Return to the archived receipt with no organic open. Several methods can store or score that record, but each leaves useful signal on the table—especially when silence produces little reward, or when eight generated candidates still yield only one user outcome.

    These are limitations, not impossibility claims. ICL helps when memory contains relevant successes. REINFORCE can learn from negative rewards. The live interaction remains the bottleneck: many generated candidates are still one user experience. Silence is ambiguous, not automatically negative. The missing piece is an interpreter that can combine sparse evidence with context and express uncertainty.

    Online-SDFT: act first, teach second

    Online Soft-Distillation Fine-Tuning adds that interpreter as a post-decision teacher. The student must generate its own route without privileged state. Only afterward may the teacher combine context, the chosen action, factual feedback, and other permitted post-decision signals into a soft target.

    Unlike typical batch soft distillation, targets are created after each live action, requests arrive once in order, the student generates every served action, and success is measured while learning—not only after a training phase ends.

    Learning while serving

    The reported experiment runs three paired streams of 240 requests across consecutive regimes: weekday → on-call → off-hours. Metrics are online accuracy (was the pre-update action the evaluator’s best route?) and cumulative regret (utility lost versus the best route, summed over the stream). The evaluator may use a hidden utility vector only for scoring; it never enters a prompt, teacher target, reward, or gradient.

    What this shows—and what it does not

    Supported

    Under a strict causal interaction loop, a soft post-decision teacher can train a small policy more effectively than hard teacher samples, short memory, or retrieval on these streams.

    Supported

    The implementation preserves the order: student rollout, one factual outcome, teacher, then online update for future requests.

    Not established

    Three seeds do not support a broad claim about all users, devices, or drifting environments.

    Not established

    The simulator’s utility weights are a declared product model, not a universal measure of notification quality.

    Act without privileged information. Observe only what the action caused. Learn from the teacher, not an oracle label. Let the update help only future requests.

    That is the difference between replaying a dataset and learning online. Continual personalization needs the second loop whenever preferences and contexts keep changing.
